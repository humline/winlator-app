## Phase 1 — Protect user data during updates (highest priority)

### 1.1 Staged rootfs installation
Rework `RootFSInstaller.install()`:

- Extract `rootfs.tzst` into `files/rootfs.staging/` via `TarCompressorUtils.extract()`. Never call `clearRootDir()` on the live rootfs before validation succeeds.
- Validate the staging directory through a new pure-Java `StagedInstaller.validate()` that returns typed errors: required paths present (`.winlator`, `opt/wine`, `etc`, `tmp`, `home`), extraction success flag, file count / total size vs archive metadata.
- Switch only after validation: rename `rootfs` → `rootfs.prev`, rename `rootfs.staging` → `rootfs`. On any failure — or a failed first startup — restore `rootfs.prev`.
- Delete `rootfs.prev` only after the first container launches successfully (tracked via a flag in `RootFS` / preferences).
- Extend `RootFS.find()` to tolerate the staging/prev directories and expose `hasBackup()` / `rollback()`.
- Route the reinstall path in `SettingsFragment` (`BTReinstallSystemFiles`) through the same staged flow.

### 1.2 Storage checks and migration warnings
- Before rootfs install and before `WineUtils.updateWineprefix()`: require free space ≥ archive size × 2 (staging + final) plus prefix working space; otherwise show a blocking dialog ("not enough storage — free X MB or back up") instead of failing mid-way.
- Before any Wine-prefix migration (`wineprefixNeedsUpdate`, `applyGeneralPatches()`), show a recovery dialog: **Backup now / Continue without backup / Cancel**.

### 1.3 Export / restore (backup) flow
New `com.winlator.core.BackupManager`:

- Export archive (`.wcb`, zstd-tar via `TarCompressorUtils`) containing: the container dir `home/xuser-<id>` (including `.wine` and `container.json`), its shortcuts, `files/profiles` input profiles, and env-var extras; plus `manifest.json` (app version, `rfsVersion`, driver versions, SHA-256 per entry).
- Restore: verify checksums first; never overwrite — allocate a new container id (reuse the `ContainerManager` copy path) and report conflicts per item.
- UI: "Export / Import" entries in `ContainersFragment` (per-container context menu) and `SettingsFragment` (global profiles / shortcuts).

### 1.4 Fault-injection tests for the risky paths
Add `app/src/test` plus `testImplementation 'junit:junit:4.13.2'` to `app/build.gradle`:

- Keep the new logic pure Java (`StagedInstaller`, `BackupManager`, `IntegrityVerifier`, `StorageChecker`) so it runs on the JVM.
- Fault-injection cases: interrupted extraction (partial staging), corrupt archive (checksum mismatch), insufficient storage, failed validation → assert rollback leaves the old rootfs intact; failed restore → assert no existing data is overwritten.

### 1.5 External devices — hide Android mouse cursor (small, independent)
Formerly item 5 of the idea; folded in here because it is a small, early win:

- In `XServerDisplayActivity` (sandbox running) with an external mouse **and** keyboard connected: hide the system pointer on the root view via `view.setPointerIcon(PointerIcon.getSystemIcon(this, PointerIcon.POINTER_ICON_TYPE_NULL))`; restore `POINTER_ICON_TYPE_DEFAULT` on device disconnect or sandbox exit.
- Detect devices via `InputDevice.getDeviceIds()` (`SOURCE_MOUSE` / `SOURCE_KEYBOARD`) plus `InputManager.InputDeviceListener`; integrate with the existing `capture_pointer_on_external_mouse` preference and `TouchpadView.onExternalMouseEvent()`.
- Add a setting "Hide system cursor with external mouse" (default on).

## Phase 2 — Driver updates and selection

### 2.1 Versioned, verified driver packages
- Add `manifest.json` + SHA-256 to each `graphics_driver/*.tzst` and `GeneralComponents` package; verify before extraction in `GeneralComponents.extractFile()` and `XServerDisplayActivity.extractGraphicsDriverFiles()`.
- Extract into a staging lib directory and swap; keep the previous `libvulkan_freedreno.so` / `libvulkan_vortek.so` / `libGL.so.1.7.0` until a smoke validation (e.g. `GPUHelper.vkGetApiVersion()` / context creation) passes; roll back on failure.

### 2.2 Preserve container driver config; show active driver
- Ensure app-level driver package updates never touch per-container `graphicsDriver` / `graphicsDriverConfig`.
- In `ContainerDetailFragment`, show active driver names + package versions (from `GeneralComponents` identifiers and `DefaultVersion`) and the effective cache id.

### 2.3 Adreno 8xx heuristics review
- Keep Turnip as the primary Vulkan candidate on Adreno 830, Vortek as the selectable alternative (already the case in `GraphicsDrivers.getItems()`).
- Replace model-number-only decisions (`GPUHelper.getAdrenoModelId()` → forced defaults / heap / gmem / sysmem) with device-probed capability checks where possible; leave heap / present-mode defaults unchanged until Phase 3 data exists.

### 2.4 Graphics diagnostic screen
New `GraphicsDiagnosticsDialog` / fragment:

- Show: GPU renderer / vendor / version (`GPUHelper`), Vulkan API version + device extensions (`vkGetApiVersion`, `vkGetDeviceExtensions`), selected Vulkan / OpenGL drivers + versions, wrapper paths (`GeneralComponents.getDefinitivePath()`), and env overrides produced by `TurnipConfigDialog.setEnvVars()` / `VortekConfigDialog`.
- Copy-to-clipboard button; accessible from `SettingsFragment` and container settings.

## Phase 3 — Performance tuning (Snapdragon 8 Elite / Adreno 830)

- **Benchmark protocol**: same device, game scene, resolution, container, driver, thermal state; track frame-time consistency, sustained performance, and crashes — not just peak FPS. Add a lightweight frame-time logger in the renderer path writing CSV per run for repeatable before/after comparison.
- **Driver A/B**: Turnip vs Vortek on Vulkan workloads; Zink vs Gladio on OpenGL workloads; test each available present mode per workload (`GPUHelper.VkPresentMode`, already per-driver config) — keep settings configurable, no global "fastest" mode.
- **Box64 presets and CPU cores**: benchmark `Box64PresetManager` presets and `CPUListView` assignments; prefer conservative defaults; expose experimental tuning per container or shortcut only (extend the existing `ShortcutSettingsDialog` override pattern) so one game's optimization cannot destabilize others.
- **Shader stutter / memory**: measure shader compilation stutter, memory use, and performance after extended play; do **not** raise GPU heap limits or disable synchronization globally without evidence that it helps and stays stable.
- **Compatibility smoke suite** after every driver or renderer update: launch, gameplay, resolution change, suspend/resume, repeated launches (checklist doc + scripted steps).

## Phase 4 — Release and recovery

- Ship driver changes vs rootfs / Wine changes as separate, reversible units (lean on the `GeneralComponents` component versioning).
- Test upgrade + rollback on **copied** containers first (use the `ContainerManager` copy path); verify user containers and shortcuts remain intact (extend the Phase 1 tests).
- Release-notes template: tested device / GPU, driver versions, settings, known issues, backup/restore instructions — published with every update.
- Roll out experimental driver defaults only after stability and performance results show a clear benefit; otherwise leave current defaults unchanged.

## Assumptions and risks

- Same-filesystem renames under `files/` give near-atomic switches; still keep `rootfs.prev` until first successful launch as insurance.
- Unit tests will be plain JUnit (no Robolectric) by keeping the new logic UI-free; a small manual QA checklist covers the Android-only paths.
- `manifest.json` checksums require a one-time generation step for existing asset packages (build-time script or first-run migration).
- The benchmark harness is instrumentation, not automated CI — it needs real Adreno 830 hardware.
